# 音频导入工具

把原始素材放入根目录 `audio/`，双击根目录的 `import_audio.cmd`。成功后重启游戏试听。无需更改台词代码，文件名与游戏引用保持一致。

```text
audio/
  bgm/曲目.ogg
  voice/角色ID/台词ID.wav
  ambience/环境音.ogg
  sfx/音效.ogg
       ↓
game/audio/（保持同样目录与文件名）
```

只有 `bgm` 与 `voice` 归一化；`ambience` 与 `sfx` 原样复制，文件内容完全一致。WAV 输出16位PCM，OGG输出Vorbis；保持输入格式及采样率（Opus使用48000Hz），不裁剪、不改变播放速度。BGM支持WAV、OGG、MP3、FLAC、Opus、MP2；配音限WAV／OGG，与现有自动查找接口一致。

## 目标与调整

`config.json` 的初始值：配音 −16 LUFS，BGM −18 LUFS，真峰值目标均为 −2 dBTP。此处均为进入游戏混音前的素材值，不是游戏最终总输出标准。游戏内语音／音乐滑块及相对增益继续控制前后景关系，电话滤镜仍由游戏自动应用。

目标值不是唯一标准，但要稳定；它同时影响素材一致性和峰值余量。先以本配置试听，再修改目标重导入即可。BGM在游戏内通常会被进一步降低音量，因此素材值不等于它在对白下的实际音量。

FFmpeg使用两次分析处理的 `loudnorm`，条件允许时采用固定增益，峰值不足时会转为动态处理／限制峰值；不会强制缩小输入的响度范围。压缩格式编码后重新测量真峰值，必要时再小幅降低增益，因此最终响度不一定精确等于目标。默认单文件最多提升12 dB，避免异常低音量素材被大幅放大。无法测量的静音／超短文件报错，保留游戏旧文件；请先检查原件。

当前按每个文件处理：这会拉近角色不同句子的响度，也可能削弱轻声与喊叫的相对差异。对于特意轻声或强烈情绪的句子，需要试听后在演出混音层微调；短音效不采用此方法。

## 使用与结果

1. 放入根目录 `audio/` 对应位置。新曲目仍需先在剧情中增加播放引用；工具只负责处理与复制。
2. 双击 `import_audio.cmd`。窗口会列出归一化、复制、跳过及失败文件，完成后保留窗口。
3. 查看 `.build/reports/audio_import.json`，记录原件／输出摘要、处理前后响度、峰值、处理模式与异常。
4. 重启游戏试听。

根目录原件不会被修改。每次始终从原件生成，绝不读取游戏副本作下一次归一化输入。未改变的原件、配置、工具代码、FFmpeg且游戏副本摘要仍匹配时跳过；原件变化、处理程序变化或游戏副本被覆盖时自动重做。输出经过处理和复测后才替换旧文件，失败不会覆盖该文件的旧音频；其他文件仍可完成。扫描／命名错误在写入前统一报错。峰值复核允许测量／编码误差最多0.3 dB；超过则导入失败。

不删除未出现在输入中的游戏文件。删掉根目录原件不等于删除游戏资源。如果切换同一句的WAV／OGG格式，先手动归档旧游戏格式；工具会阻止同名多格式，避免WAV优先查找导致替换无效。

配音以现有 `.build/exports/chXX_manifest.json` 检查角色ID、台词ID、台本摘要；徐启星和所有内心不在配音清单中，禁止导入。台词源更新后先重新导出该章录音清单。工具只能检查命名与登记，不能听辨音频是否说了正确的内容。

## 依赖与命令

只需要Python 3.11以上与FFmpeg，不依赖工程的 `.build/deps`。本机启动入口优先使用Codex已提供的Python，再尝试系统Python。`config.json` 暂指向本机现有FFmpeg，迁移电脑后改为新的FFmpeg路径；也可以留空使用系统路径中的 `ffmpeg`。不自动下载或安装依赖。

```text
python tools/audio_import/import_audio.py --dry-run
python tools/audio_import/import_audio.py
python tools/audio_import/import_audio.py --force
python tools/audio_import/import_audio.py --ffmpeg "可执行文件路径"
python tools/audio_import/test_import_audio.py
```

`--dry-run` 只扫描并验证，不改音频或报告。`--force` 从原件重新生成所有扫描到的文件。测试使用临时生成的音频，不触碰真实游戏素材。
