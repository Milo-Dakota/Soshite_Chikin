# 制作工作流

Agent 负责剧情研究、章节细分、日语台本、隔离中文翻译、美术生成、Ren'Py 实装与必要检查。人类提供全部音频（含配音）、操作导入并反馈游戏效果。日常制作不包含许可证核查或发布记录管理。

1. 读当前状态、章节总计划、故事总览及本章原文，确认原文版本与授权范围。
2. 写 docs/chapters/chXX/plan.md：Scene、视点、地点、人物、剧情作用、情绪及演出意图；只细分当前章。
3. 写 scripts/ja/chXX.yaml，对照原文检查剧情、梗及视点，固定 ID。
4. 在未读原文的独立上下文中，从日语及汉化指南生成 scripts/zh/chXX.json，以 ID 和日语摘要绑定。没有隔离环境时明确说明并另行安排，不自动启动多 Agent。
5. 本章 assets.md 记录需求与复用安排。先复用核对，再角色／服装 Reference 和空间关系，再背景与基础立绘、表情／姿态、CG 和道具；特殊构图可先做草案。
6. 向人类提供稳定的录音稿与音频需求。少量交接用聊天，批量事项才建 handoff/chXX/audio.md、voice.md 或 review.md；不默认生成 HTML。
7. Ren'Py 实装贯穿制作：双语就绪可先接阅读版，美术／音频分批完成分批接入。最终演出维护在 scripts/staging，不积累多层临时覆盖。
8. 按实际变更检查台本、字幕、素材、语音路由及必要的游戏顺序运行和布局；按反馈修正。用户确认完成后更新 status，收起交接，不自动开下一章。

## 音频流程

人类原件 → audio/bgm、voice/角色、ambience、sfx → 根目录 import_audio.cmd → game/audio。

BGM／voice 归一化，环境音／SE 原样复制。Agent 配置播放时机；导入不自动新增播放引用。电话／电视滤镜、相对音量属于游戏演出。

## 文件职责与变更

- plan 保留剧情研究与 Scene 意图；assets 保留创作要求；staging 只解释特殊演出设计。当前完成状态不重复维护。
- 文件映射、参考关系、生成提示词在 assets/records；机器检查报告在 .build/reports。
- 录音清单、录音阅读稿、双语阅读稿输出到 .build/exports。确需录音交接时才复制到 handoff/chXX/voice.md。
- 改日语须复核中文、朗读、配音及实装；仅改镜头不要求重录／重译未变台词。工具报告绑定源摘要，过期产物不得当成最新。
- 检查按当前变更执行，不反复跑无关检查。缺实际产物须明确记录，不能以占位资源冒充完成。过期记录和一次性临时文件及时清理，不追加到当前说明末尾，不专门为历史留档建立备份。

## 信息维护位置

| 信息 | 维护位置 | 其他文档如何引用 |
|---|---|---|
| 章节进度、当前任务、待办、阻塞与验收结论 | `docs/status.md` | 链接到 status，不复述“已完成／未开始／待验收” |
| 故事事实与原文证据 | `docs/story/`、对应章节 `plan.md` | 保留各自依据的原文 SHA、行号及适用范围；这是证据版本，不是制作进度 |
| 正式日语、中文、ID 和章名 | `scripts/ja/`、`scripts/zh/` | 不抄写台词总数／最新 revision；需要时读取源或重新导出 |
| 专名读法、角色语言与中文固定译名 | `character_language.md`、`localization_guide.md` | 前者服务日语制作，后者是隔离汉化所需独立输入；专名变化时同步对应项，不传入原文研究 |
| 美术创作要求、选用原件与参考关系 | 本章 `assets.md`、`assets/records/` | 文档说明要求，记录保存文件关系；不重复维护全量清单或交付状态 |
| 镜头时机、等待时长、素材声明和混音参数 | `scripts/staging/`、对应 `game/` 公共运行代码 | `staging.md` 解释设计意图，不复制秒数、增益及逐行指令 |
| 游戏版本、画布、字体、字号和界面尺寸 | 对应 `game/` 配置与样式 | `docs/ui/` 说明视觉原则及代码入口，不维护第二套参数表 |
| 音频处理目标和工具依赖 | `tools/audio_import/config.json`、根目录 `requirements.txt` | 使用说明引用配置，不抄录当前参数和安装版本 |
| 检查结果与导出清单 | `.build/reports/`、`.build/exports/` | 可重新生成；报告只对检查时的输入有效，不代替 status 的验收结论 |

普通制作任务收尾时，在 status 更新本次任务结果与必要待办；若只推进进度，不改其他文档。只有规则、剧情理解或设计本身变化时才修改对应文档。

`handoff/` 只保存必要的交付操作详情；status 链接交接文件，不复制其全部条目。事项结束后收起交接文件。正式汉化上下文不读取本文件或 status，由发起任务方提供规定的隔离输入。
